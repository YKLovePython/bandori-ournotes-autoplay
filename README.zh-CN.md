# 《BanG Dream! Our Notes》人机协同自动演奏（免 root）

> **你按第 1 个音符，脚本从第 2 个音符起把这首歌打完。**
> 整机原厂 Android，不用 root、不用模拟器、不用无障碍服务。

## 这是什么

一套跑在**未 root 的原厂安卓手机**上的《BanG Dream! Our Notes》（2026 年新作）自动演奏，
只通过普通 ADB 连接。

设计上刻意保留"人"在环里：

1. 你选歌；
2. 脚本替你点 **LIVE START**；
3. 第 1 个音符压到判定线时，**你自己按**；
4. 脚本从**第 2 个音符**接手，把剩下的打完。

你按下之后的一切都由游戏自己的谱面数据驱动：点击、长条、**会横移的长条**、
以及轻扫音符（上 / 左 / 右）。

---

## 它不一样在哪

截至 **2026‑09‑30**，这个游戏我们没有找到任何公开的自动演奏成品；能找到的相近项目
都是**老邦邦**的，而且需要 root 或模拟器。下面几条是它能在一台原厂机上跑通的原因：

**1. 用你自己的手指当时钟，而不是猜。**
谱面文件里没有前摇时长，加载时间又会变，所以"点完开始键等 N 秒"这类做法必然不稳：
同一台机器同一天，实测标定值在 **2.12s / 9.53s / 10.05s / 11.52s** 之间跳，
错了就是整首歌全 miss。这里改成读原始触摸屏，取你第一下的**内核时间戳**当基准，
后面全部按它排程。因为用的是内核时间戳，"读得慢"只会让我们晚一点开打，
不会让落点偏。

**2. 通过虚拟 HID 触摸屏注入，不用 root。**
现代原厂机的 SELinux 会拒绝 `sendevent`，`adb shell input` 又只能单指、还慢 60~80ms。
这里走的是 **scrcpy‑server 的 UHID**：系统里多出一块真正的 HID 数字化仪
（`TOUCH | TOUCH_MT`），游戏分不出真假。

**3. 谱面驱动，不靠看图。**
画面只用一个很粗的判断（现在是不是乐队确认页）。音符位置和时刻全部来自游戏谱面数据，
不依赖从视频流里识别音符——那条路正是早期版本会"越打越偏"的原因。

**4. 长条是"跟着走"，不是"原地按住"。**
我们解析过的 340 张谱面里，**23073 根长条有 15311 根会横移**（不只是头尾不同，
有些是滑出去又滑回来）。实测横移速度：中位 1258 px/s，90 分位 4346 px/s。
如果每个谱面节点（约 157ms）才动一次，单步位移中位 **197 像素**，跟音符条本身的
容错同一量级——手指有一半时间在条外，所以是"有概率 miss"。
现在按**位移**重采样（每走约 50px 发一次划动，同一根手指最快 40Hz），
单步中位降到 **72 像素**。

**5. 尾巴要轻扫的长条。**
**23073 根长条里有 2512 根尾巴是轻扫**（上滑 1536 / 左滑 492 / 右滑 484）——
要"一直按着，到最后再划出去"；另有 200 根是头部就要划。两种都按真实手势实现：
先贴到条子尾巴的位置、再划出去、最后松手。

## 和现在能找到的项目比，差在哪

动手之前我们查过同类项目。下面不是在贬低谁——其中几个正是这套方案能成立的前提——
但差别恰好就是这个项目的价值。

| 项目 | 游戏 | 需要 root / 模拟器 | 时间基准是什么 | 手势覆盖 |
| --- | --- | --- | --- | --- |
| **phisap**（★211） | Phigros | 不需要（用 scrcpy） | **每次运行由人打一下拍**（半自动） | 点击、长按、拖动 |
| bandori‑cv‑autoplay | **老**邦邦 | **需要 root 或模拟器** | 计算机视觉 | 视觉推导 |
| Autodori（2019） | **老**邦邦（iOS） | 越狱 / AutoTouch | 计算机视觉 | 有限 |
| **本项目** | BanG Dream! **Our Notes** | **都不需要** | **玩家自己第一下的内核时间戳** | 点击、长按、**横移长条**、**尾巴轻扫**、独立轻扫 |

"让人参与对时"这个思路并不新——phisap 就是让人打一下拍，它的作者也在注释里写过
（大意）"其实用音频流对齐时钟才是正解，可惜平台版本不够"。这里不一样的地方是：

* 基准是**游戏内一次真实命中的内核时间戳**，不是对着节拍器打的拍子——
  也就是说锚点本身就是游戏已经接受的一刻；
* 它**一次用一整首歌**，而不是一个需要在多次运行之间维持的标定值
  （我们实测那套"猜"的办法，标定值在 9 秒的范围内跳）；
* 演奏过程中**没有任何一环依赖视觉**，所以没有会误检的检测器；
* 手势模型是**把 340 张谱面全量统计**出来的（多少长条会动、动多快、多少尾巴要甩），
  而不是"把常见情况处理了就收工"。

这个项目**没有**走到的地方也说清楚：不读游戏内存、不折腾 `sendevent`、
不做纯视觉兜底、也不自动化第一个音符。这些是有意划的边界，不是漏掉的功能。

## 实测结果（小米 2510DRK44C，Android 16，未 root）

| 指标 | 数值 |
| --- | --- |
| 锚点精度（第 1 下落点 vs 谱面） | 误差约 0.2 格以内 |
| 触摸读取 + 注入的往返延迟 | ≈ 1 ms（常驻 adb shell 自身往返 0.7~1.5 ms） |
| 全谱面回归（340 张读取 + 排程） | 0 失败 |
| 整首歌的动作 | 全部发完，日志可核 |
| 长条跟随单步位移 | 中位 72px（原来 197px） |
| 峰值注入速率 | 中位 26/s，最大 94/s（原来 232/s） |

## 一句话讲原理

```
你选歌 ──► 脚本点 LIVE START ──► 你按第 1 个音符
                                        │
                                        ▼
                              取那一下的内核时间戳 = 基准
                                        │
                                        ▼
       谱面数据（340 首：点击 / 长条 / 轻扫，长条带轨迹）
                      │
                      ▼
   脚本把剩下的每个音符排成"按下 / 划动 / 抬起"的动作表
                      │
                      ▼
        通过虚拟 HID 触摸屏（scrcpy-server UHID）注入
```

更完整的说明见 [docs/how-it-works.zh-CN.md](docs/how-it-works.zh-CN.md)。
