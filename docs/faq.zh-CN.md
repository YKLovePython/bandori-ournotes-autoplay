# 常见问题

**问：源码在哪里？**
已经全部公开：**[YKLovePython/ournotes-autoplay](https://github.com/YKLovePython/ournotes-autoplay)**
（Release 里有免环境的 Windows 版）。本仓库是介绍与存证页，实现代码在那边。

**问：我的手机能用吗？**
开发和实测都在小米 2510DRK44C（Android 16，未 root）。原则上只要这台设备
（a）能接受 scrcpy 的 UHID、（b）允许 `getevent` 读触摸屏，就能用；
面板尺寸、判定线几何、LIVE START 按钮位置都是按设备标定的。

**问：为什么不用 `adb shell input tap`？**
它每次都要新起进程，60~80ms 一次，而且只能单指——双押和长条根本做不了。

**问：为什么不像别的音游脚本那样做视觉识别？**
视觉告诉你"音符在哪"，而谱面已经精确告诉你了；视觉还会带来 25~40ms 延迟和偶发误检。
这里画面只用来认"乐队确认页"这一个粗判断。

**问：为什么不直接读内存 / 为什么不用 root？**
这台手机就是未 root、BL 锁定的原厂状态。这个约束正是这个项目有意思的地方。

**问：这算不算作弊？会不会封号？**
自动化游玩在线游戏违反其服务条款，账号可能被处罚。这里作为研究项目公开，不是给你拿去用的
工具。请看免责声明。

**问：为什么第 1 个音符一定要人按？**
因为那一下就是时间基准。谱面里没有前摇，加载时间还会差好几秒。
这不是"没做完的功能"，而是这套方案的核心。

**问：还剩下的那些 miss 是什么？**
集中在**最快的滑条**（残余误差来自你自己第一下就有几十毫秒的偏差，
条子以 4000px/s 滑动时这个偏差会被放大），以及**尾巴要甩一下的长条**偶尔失手。
两者在[技术思路](how-it-works.zh-CN.md)里都写了机理和实测数字。
